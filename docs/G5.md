# G5 — Yakalanan uydurma

Ders PDF'sinin 31. sayfasındaki token ekonomisi tablosu “Yakalanan uydurma (G5)” ölçütünü verir. PDF sayfa 30, uygulamayı ayağa kaldıramadığı hâlde testlerin geçtiğini söyleyen ajan raporunu tipik hata olarak örnekler. Transkript 37:37 de doğrulanamadığı yerde uydurmak yerine durmayı anlatır.

## Git geçmişinde gerçekten yazılıp düzeltilen yanlış iddialar

1. README, Capterra acısını doğrulanamayan “Ryan P., Facilities Services, 10.001+ çalışan” kimliğine bağladı. `git show 95dab84^:README.md` yanlış atfı, `95dab84` farkı ise Hadi B. düzeltmesini gösterir. Kaynak sayfası yeniden incelenerek kişi, tarih ve ürün doğrulandı.
2. README canlı #2 iş akışında dört işlem geçmişi olayı bulunduğunu yazdı. `git show 95dab84^:README.md` dört olay iddiasını, `95dab84` farkı beş olay düzeltmesini gösterir. Oluşturma, atama, otomatik `new → open`, yanıt ve `open → solved` ayrı olaylardır; canlı detay ve workflow testi beşini doğrular.

Bu nedenle ajan ölçüm tablosundaki doğrulanmış yanlış iddia sayısı **2**'dir.

## Uydurma sayısına dahil edilmeyen doğrulama düzeltmeleri

- PostgreSQL istemci mesajı tek başına kök neden kabul edilmedi; olay günlüğü ve başarılı migration/test ile eksik veritabanı teşhisi doğrulandı. Bu bir teşhis düzeltmesidir, yazılmış yanlış ürün iddiası değildir.
- Box hikâyesinin Fortune 500 şartını tek başına kanıtlamadığı fark edildi. Eski README zaten boşluğu açıkça “eksik” yazdığı için bu, yakalanan uydurma sayısına eklenmedi.
- Zendesk'te SLA yokluğu iddiası belgeye alınmadan reddedildi; Zendesk SLA/Explore belgeleriyle karşılaştırma sınırı yazıldı. Git geçmişinde yayımlanmış yanlış iddia olmadığı için sayıya eklenmedi.

Box kaynak boşluğu daha sonra Zendesk'in SEC'e sunduğu 2018 Q1 hissedar mektubuyla kapatıldı: belge Stanley Black & Decker'ı Fortune 500 şirketi olarak tanımlıyor ve dört Zendesk ürününü içeren anlaşmayı açıklıyor.
